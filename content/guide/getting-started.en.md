# Getting started

<p class="kicker">GETTING STARTED</p>

## Two layers of directories

```
content/   The only hand-written layer. Filenames carry a language suffix:
           guide/index.zh-hans.md, guide/index.en.md
docs/      The build layer. Every .md here is produced by tools/docsgen.py
```

Each `.md` under `docs/` carries a banner saying “generated by tools/docsgen.py, do not
edit by hand”. That banner *is* the test for “which files are generated”, so no separate
manifest is needed. Hand-written `docs/**/*.md` carry no banner and are never pruned.

!!! warning "Always regenerate after editing content/"
    `docs/` is **committed to the repository**, and the build reads it directly. Edit
    `content/` without running `make gen` and the build silently ships the old text —
    nothing errors.
    Both `make build` and CI run the generation step first, precisely to close that gap.

## What one command runs

```
make build = docsgen → navgen → zensical build --strict → tagfilter → linkcheck → i18n_check
```

The last three are checks on the **build output**; source-level validation cannot see them:

* `tagfilter` — the tag index is filtered per language (the plugin scans all of `docs/`,
  so it would otherwise list pages of other languages);
* `linkcheck` — internal references, directory trailing slashes, redirect stub targets;
* `i18n_check` — missing, stale, or structurally mismatched translations.
