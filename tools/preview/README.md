# 本地热更新预览

改 `content/` 下的文件、存盘，浏览器里的页面自己刷新。不用每次都找人开。

## 怎么用

**双击 `start.bat`**——服务起来后会自动用默认浏览器打开预览，地址不用自己粘。

改 `content/` 下的文件、存盘，页面一秒左右自己刷新。存盘后页面动了才说明这轮走完。
（不想让它自动弹浏览器：加 `--no-open`。）

## 为什么慢，以及现在为什么快

原先是每存一次盘就跑一次 `zensical build`。**`zensical build` 没有增量能力**：
连着跑两次、第二次什么都没改，实测一样 3.3 秒——827 个产物、53 MB，整个重来
一遍。快慢的差别几乎全在这一步。

现在改成**常驻构建器**：另起一个 `zensical serve` 子进程（跑在内部端口 8000+1000
上），它记住上一轮的状态，改一页只重写变了的那几十个文件（实测 site/ 里只有
42/851 被重写，**0.15 秒**）。HTTP 服务与浏览器刷新仍归本脚本自己管——子进程只管
把 `docs/` 构建进 `site/`，这一头一个字都没让出去。

一轮下来各段实测（改一个 `content/` 文件，同一台机器）：

| 一段 | 原来 | 现在 |
| --- | --- | --- |
| 轮询发现改动（`tools/watch.py` 的间隔） | 0～1 秒 | 0～0.25 秒 |
| 等编辑器写完（防半截保存） | 固定 0.8 秒 | 静默 0.15 秒就走，最多 0.8 |
| docsgen + navgen（绕不过） | 0.6 秒 | 0.6 秒 |
| 重建站点 | 全量 3.4 秒 | 增量 0.15 秒 |
| **存盘 → 页面更新（实测）** | **约 6.4 秒** | **约 1.5 秒** |

另外还砍掉两笔纯亏的：

- **每轮 `rmtree(.cache)`**：清缓存只让构建更慢（实测 4.0 秒 vs 3.3 秒），毫无收益。
- **每轮把 `docs/en`、`docs/zh-hant` 挪出去再挪回来**：实测省不下时间（3.35 vs
  3.29 秒），却让预览里的英文页、繁体页 404。现在三种语言的产物都在，随便点。

顺带修掉一个会整台塌掉的毛病：脚本里打的 `✓`、`…` 在 GBK 控制台上会
`UnicodeEncodeError`——构建成功、打印那一行时崩，服务根本没起来。双击 `start.bat`
因为先 `chcp 65001` 所以看不出来，别的启动方式会撞上；现在启动就把 stdout 钉死在
UTF-8。

`zensical build` 本身**没有增量选项**（只有 `-f / -c / -s`），所以每轮一次全量那条
路绕不过去——常驻构建器是唯一的解法。换 mkdocs（有 `--dirty`）也不可行：仓库用了
zensical 特有的 `langutil` 模板函数和它的插件，`zensical.toml` mkdocs 不认。

万一带子进程这条路起不来（本机历史上见过一次 `os error 5`），脚本会自动退回原来
的「每轮全量构建」，慢一点但一样能用，并在终端里说一声。

## 页面这一头

- **改完直接重绘**：构建完不整页刷新，而是取新页面把 `<article>` 换掉，滚动位置
  保留——CSS/JS 不用重新下载。带页内搜索的页（五张清单、下载页）脚本只在加载时
  初始化一次，这类页自动退回整页刷新。
- **推送式**：服务端一条常驻 SSE 连接，状态一变就推（不再是每 1.5 秒问一次）；
  重建过程中右下角挂一条「正在重建…」，免得页面毫无动静、看着像卡住。
  EventSource 起不来（老浏览器、代理掐长连接）才退回原来的轮询。

## 为什么还要自己写这一层

`zensical serve` 只盯 `docs/`（那是生成物目录），改 `content/` 它一声不响；
而且它**不带浏览器自动刷新**——实测它发出来的 HTML 里没有任何 livereload 代码，
指望不上。所以「盯手写层、注入刷新、把状态推给页面」这三件事仍旧由本脚本自己来，
只把它当一个增量构建器用。

## 预览不做任何体检

预览只做三件事：**生成 docs/ → 构建 → 让浏览器刷新**。链接体检、翻译度体检、
版本体检**一律不跑**——它们不参与「我改的能不能立刻看见」，跑它们只会让每次
存盘多等。

那些留给 **`fullcheck.bat`**：等你说「统一处理一下」的时候再跑，一次跑完并给
汇总（哪步没过、英文没跟上的话该跑哪条命令）。想让预览也顺手体检就加 `--check`
（默认关）。

⚠️ 跑 `fullcheck.bat` 之前**先双击 stop.bat 关掉预览**：预览正服务着 `site/`，
   构建要清理它，两边会撞（表现是 `site directory could not be cleaned`）。

## 改了简中之后，另外两种语言怎么办

三种语言的来源不一样，改一个文件的后果也不一样：

| 语种 | 要不要你动手 | 说明 |
| --- | --- | --- |
| 简中 `zh-hans` | **手写** | 唯一的手写层，改这里就对了 |
| 繁体 `zh-hant` | **不用管** | 由 docsgen 从简中**脚本转写**派生，存盘即同步，不可能过期 |
| 英文 `en` | **要跟进** | 手写译文，原文动了它不会自己变 |

所以「只改了简中一个文件」是对的——**繁体已经自动跟上了**，真正需要盯的是英文。
但这一条在页面上看不出来：预览会照常显示英文那份旧译文，看着一切正常，
等发版 CI 才红（判据是译文里记的 `source_sha256` 与原文对不对得上）。

这件事预览**不提醒**（它不做体检），由 `fullcheck.bat` 一次跑完并点名：

```
[en · 已过期] content/tables/wall.en.md
    原文 content/tables/wall.zh-hans.md 已改动。重读源文件，更新
    content/tables/wall.en.md，然后把 source_sha256 改为 7a4ec362…

翻译度：已过期 1　已同步 25
  还没跟上（会挡住构建）：
    [en] content/tables/wall.en.md  ·  stale
    改完英文后，用这条把指纹更新（一次一条）：
      node _refingerprint.js rwr-mapbook/content/tables/wall.zh-hans.md:rwr-mapbook/content/tables/wall.en.md
```

英文**怎么翻**工具替不了（那是人做的事），但「哪几页没跟上、翻完该跑哪条命令」
它会一次说清，不用你自己记得去跑 `make check`。

## 怎么关

- 正在跑的那个黑窗口里按 **Ctrl-C**，或者直接**关掉窗口**——最省事。
- 窗口已经关了、端口还占着（或者你忘了开在第几个窗口）：**双击 `stop.bat`**。
  它会找出是谁在监听 8000、把进程名打给你看，然后结束掉。别的端口就
  `stop.bat 8010`。
  内部那个构建器（8000+1000，也就是 9000）它也会一起清——不然它继续占着
  `site/`，下次启动会撞。真漏了也没关系：`serve.py` 启动时自己扫一遍，
  看见上次留下的构建器会替你清掉。

## 端口被占怎么办

启动时如果 8000 已经被别的东西占了，脚本会明说，三条路随你挑：

```
start.bat --port 8010      换一个端口
start.bat --auto-port      让它自己找空位（8000 被占就试 8001、8002…）
双击 stop.bat              把占着的那个关掉，再正常开
```

`--auto-port` 会在终端里告诉你实际用了哪个端口（`顺延到 8001`），
看一眼再粘进浏览器就行。

⚠️ `stop.bat` 会**强制结束占用该端口的进程**。端口上跑的确实是你自己那个
预览时才用它；万一 8000 上是别的程序（另一个项目的服务之类），
它会一并结束——跑之前看一眼它打出来的进程名。

## 想快点开（跳过启动时的构建）

`site/` 已经是新的、只想开着看：

```
python tools/preview/serve.py --no-build
```

这样几秒就起来（不建站、也不起构建器）。改了 `content/` 之后它照样会重建——
第一笔改动会把构建器拉起来，那一次要全量建一遍（约 4 秒），之后就是增量了。

## 它到底在做什么

```
手写层有改动  →  docsgen + navgen（content/ → docs/）
              →  常驻构建器（zensical serve）只重建变了的那几页 → site/
              →  版本号 +1
              →  页面里注入的 JS 常驻 SSE 连着，版本一变就换掉 <article>
```

盯的是这些：`content/`、`overrides/`、`docs/stylesheets/`、`docs/javascripts/`、
`docs/assets/`、`tools/*.py`、`zensical.toml`。盯梢清单与轮询间隔直接 import 仓库里的
`tools/watch.py`，不另抄一份，改了那里这里跟着变（顺手把那边的 `stamp()` 从
`Path.rglob` 改成 `scandir`：811 个文件从 **220 毫秒降到 8 毫秒**，间隔因此
敢从 1 秒缩到 0.25 秒）。

## 为什么不直接用 `make serve` + `make watch`

这台机器上那条路走不通，脚本里分别绕开了：

| 坑 | 怎么绕的 |
| --- | --- |
| 没有 `make`；`uv run` 会拉 Python 3.15，pyyaml 要现场编译而本机缺 MSVC | 用 `RWR_PYTHON` 指定的解释器，或工作区里那个便携 Python 3.14（`serve.py` 会挨个探一遍，挑真的装齐 `zensical`+`pyyaml`+`zhconv` 的那个） |
| 那个便携 Python 是**嵌入式发行版**（带 `python314._pth`），不放脚本目录进 `sys.path`、也忽略 `PYTHONPATH`，于是 `python tools/docsgen.py` 里的 `from hant import ...` 必然找不到 | 用 `runpy` 跑，跑之前显式把 `tools/` 塞进 `sys.path` |
| `tools/watch.py` 直接跑不起来（同一个 `hant` 问题，本机实测），而且生成器报错时它打的中文/符号在 GBK 控制台上会 `UnicodeEncodeError` 把自己带塌 | 本脚本自己走 runpy 那条路，并把子进程的输入输出都按 UTF-8 收发 |
| `zensical serve` 只盯 `docs/`，也不带浏览器刷新 | 只把它当增量构建器用，服务和刷新自己来 |
| `zensical build` 在**受限作业对象里**要 50 多秒、还常报 `拒绝访问 (os error 5)` | 默认走增量那条路（只写几十个文件，通常碰不上）；真退回全量时就重试，产物变新了也算成功 |

控制台里正常请求与 404 都不打——404 多半是浏览器讨 favicon、页面脚本探
`sitemap.xml` 之类，预览里全是噪音（这些在线上都有归处）。只有 5xx 这种
真错误才出现一行 `! /路径 → …`。

## 两个提醒

- 它只读手写层、只写生成物：`docs/`（生成物）、`site/`、`.cache/` 都在 `.gitignore`
  里，**正文与模板一个字都不会动**。
- 预览里**没有链接体检、翻译度体检、版本体检**——它们不参与「改完能不能看见」，
  一律留给 `fullcheck.bat`（或 `make build`）。要发版前跑那个。

## 与 `make serve` 的关系

这份工具是给**这台机器的现状**准备的（没有 make、`uv` 装不上、需要 GBK 控制台兜底）。
仓库正常的预览方式是 `make serve` + `make watch`（`zensical serve` 自带的热更新），
在装了 uv 的环境里用那套就好。两边做的事情一样：盯手写层 → 生成 `docs/` → 构建 → 刷新。
